# Возможные вопросы преподавателя

1. **Почему монолит?** ТЗ требует один сервис; для учебного домена он проще в транзакциях, запуске и объяснении.
2. **Почему POST возвращает 201?** Ресурс создан сервером; 200 был бы менее точной семантикой.
3. **Разница 400 и 409?** 400 — синтаксис/валидация запроса, 409 — корректный запрос конфликтует с текущим состоянием.
4. **Когда 404?** Когда ticket или указанная category не существует.
5. **Почему PATCH?** Меняется только подмножество разрешённых полей, а не весь ресурс.
6. **Где бизнес-правила?** В `TicketService`, а не controller/repository.
7. **Какие переходы разрешены?** NEW→IN_PROGRESS/CANCELLED и IN_PROGRESS→RESOLVED/CANCELLED.
8. **Почему нельзя reopen?** Это явное правило ТЗ; терминальные данные и метрики остаются однозначными.
9. **Что означает closedAt?** Только момент RESOLVED; у CANCELLED он null, потому что отмена не является решением.
10. **Зачем `@Transactional`?** Изменение ticket и вставка history либо фиксируются вместе, либо оба откатываются.
11. **Что такое атомарность?** Наблюдаем либо весь переход, либо исходное состояние, но не половину операции.
12. **Как предотвращена потеря обновлений?** JPA `@Version`; устаревшая версия вызывает optimistic lock conflict, преобразованный в 409.
13. **Почему optimistic, не pessimistic lock?** Конфликты ожидаются редко; нет долгой блокировки строки.
14. **Что делает JPA?** Описывает отображение Java entity на реляционные таблицы.
15. **Что делает Hibernate?** Это JPA provider: dirty checking, SQL и optimistic version.
16. **Почему `ddl-auto=validate`?** Hibernate проверяет, но не разрушает схему; версиями владеет Flyway.
17. **Что даёт Flyway?** Повторяемый порядок миграций, checksum и история применённых версий.
18. **Можно исправить V1 после deploy?** Нет; нужно добавить V3, иначе checksum расходится и история становится недостоверной.
19. **Почему PostgreSQL, не H2?** ТЗ и production semantics; Testcontainers проверяет реальные типы, SQL и индексы.
20. **Какие индексы есть?** status, priority, category, createdAt, lower(title), open dueAt и составной history.
21. **Почему partial index для dueAt?** Просрочку ищут только среди NEW/IN_PROGRESS, индекс меньше и точнее для запроса.
22. **Как работают фильтры?** Nullable Specifications собираются через `Specification.allOf`; применяются одновременно.
23. **Зачем whitelist сортировки?** Не даёт ошибочным/вложенным property превратиться в непредсказуемый запрос или 500.
24. **Что такое полуинтервал `[from,to)`?** Нижняя граница включена, верхняя исключена; соседние отчёты не дублируют события.
25. **Почему Clock внедряется?** Бизнес-время можно фиксировать в тестах без sleep и гонок.
26. **Граница просрочки?** Только `dueAt.isBefore(now)`; равенство ещё не просрочено.
27. **Где реально используется Kotlin?** `KotlinReportingService` и `SummaryReport`, вызываемые Java `ReportController`.
28. **Зачем Java-интерфейс для Kotlin?** Отделяет агрегацию от JPA и явно демонстрирует interop.
29. **Что даёт data class?** Автоматические value methods и краткий immutable DTO.
30. **Зачем nullable `Double?`?** При отсутствии RESOLVED среднего математически нет; null честнее нуля.
31. **Как Kotlin защищает null?** `closedAt?.let` возвращает значение только при non-null, `mapNotNull` убирает отсутствующие.
32. **Сколько уровней тестирования?** Unit, PostgreSQL integration и два сквозных HTTP-сценария.
33. **Почему Mockito и MockK?** Mockito удобен для Java, MockK — idiomatic Kotlin; оба показывают изоляцию зависимостей.
34. **Что делает Testcontainers?** На время тестов запускает чистый PostgreSQL Docker container и передаёт JDBC properties Spring.
35. **Почему тесты изолированы?** Репозитории очищаются перед каждым тестом, время фиксировано, порядок не используется.
36. **Что измеряет JaCoCo?** Исполненные JVM instructions/branches/classes; это индикатор, а не доказательство качества.
37. **Что проверяет Spotless?** Детерминированное форматирование Java/Kotlin/Gradle; CI отклонит расхождение.
38. **Почему multi-stage Dockerfile?** JDK/Gradle нужны при build, но в runtime остаётся только JRE и jar.
39. **Почему non-root в container?** Уменьшает последствия компрометации процесса.
40. **Разница Docker health и Actuator readiness?** Docker опрашивает endpoint; Actuator агрегирует готовность Spring и зависимостей.
41. **Как сохраняются данные?** Named volume подключён к каталогу PostgreSQL и не меняется при замене app image.
42. **Почему нельзя обычно `down -v`?** `-v` удаляет persistent data.
43. **Как устроен backup?** `pg_dump --format=custom`; restore выполняется `pg_restore` в отдельную БД и проверяется SQL.
44. **Что происходит в PR pipeline?** Только format/tests/coverage на GitHub-hosted runner; публикации и deploy нет.
45. **Почему image tag — SHA?** Он immutable и однозначно связывает runtime с исходным commit.
46. **Почему self-hosted runner опасен?** Он имеет доступ к ПК/Docker; поэтому запускается лишь защищённая main и environment approval.
47. **Как работает rollback?** До deploy сохраняется предыдущий image; при failed readiness Compose поднимает его, не трогая DB volume.
48. **Какая проблема миграций при rollback?** Старый код должен понимать новую схему; поэтому изменения аддитивны и удаление делается в несколько релизов.
49. **Почему CI/CD пока не PASS?** Нет GitHub repository, GHCR/environment и runner студента; локально подготовлены только файлы.
50. **Как не раскрываются секреты?** `.env` игнорируется, example не содержит реального секрета, CI использует GitHub token/environment secrets.
